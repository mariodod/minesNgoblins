Checks:

- The generator is deterministic; re-running `npm run assets` on an unchanged tree produces byte-identical files.
- `src/data/asset-manifest.json` is the single list of images, spritesheets, animations, and sounds. `PreloadScene` and the animation registry read it, so no second hardcoded list exists.
- The audio generator fails the run when an `SfxName` or `MusicName` union member has no generated key.
- License and origin are documented in [Asset and Dependency Licenses](asset-licenses.md), `public/assets/README.md`, and `public/audio/README.md`.

## Text clarity

The blurry text reported after M5 came from canvas text rendered at fractional scales. M6 replaced it:

- Labels render through the original 5×7 bitmap font in `src/ui/pixel-text.ts`, which patches `GameObjectFactory.text` so existing call sites keep working.
- Font sizes quantize to 7, 14, 21, or 28 px, which are whole multiples of the glyph height.
- The canvas uses `Phaser.Scale.NONE` with a computed integer zoom, so the 480×270 frame is only ever shown at 1×, 2×, 3×, or 4×. No fractional canvas scale remains.
- Glyph cells gained two descender rows, so `g`, `j`, `p`, `q`, and `y` no longer read as capitals (the Credits line previously rendered "pixel" as "Pixel").
- `setShadow` is a no-op on bitmap text; CSS-style text backgrounds are synced rectangles behind the glyphs.
- Long labels gained backing plates where they overlap scenery: the HUD control hint and the title status line.

Screens checked at 1920×1080 (4× integer scale) and at the 480×270 internal size: title, run setup, HUD, pause, options, controls, credits, achievements, skins, results, and the boss HUD. Every line stayed inside its panel after the font metric change; card, reward-row, and status-bar spacing were adjusted where the taller glyphs overflowed.

## Audio verification

- Master, music, and SFX volumes plus mute route through Phaser's sound manager, so all four cover effects and music.
- `tests/e2e/audio.spec.ts` proves a run starts music, SFX fire during play, mute silences the manager, and unmute restores the previous volumes.
- `tests/e2e/settings.spec.ts` proves every audio row cycles, persists to the save, and survives a reload.
- Music loops: `music-title` (title, options, credits, results), `music-mines` (levels 1–4), `music-boss` (Great Worm arena).
- All buffers are DC-offset corrected and normalized below full scale by the generator, so no file clips or opens with a click.
- When a browser has no Web Audio backend, preload skips the WAV pack and the game boots silently instead of waiting forever on HTML5 audio. Playback paths check the audio cache first, so a skipped pack never throws. This is what lets Playwright's WebKit build reach the title screen; real Safari has Web Audio and loads the full pack.

| Fullscreen       | On/off                          | Session only      | `accessibility.spec.ts`                         |
| Key rebinding    | Seven actions plus reset        | Save v1 as `code` | `accessibility.spec.ts`, `keybinds.test.ts`     |
| Reduced motion   | Covered by shake/flash settings | Save v1           | Unit tests                                      |

Details:

- Camera flashes go through `flashCamera`, which scales the colour for `reduced` and skips it for `off`, so a disabled flash never hides gameplay state.
- Bindings are stored as `KeyboardEvent.code` values and legacy short names (`SPACE`, `ESC`, `A`) upgrade on load. Duplicate bindings in a hand-edited save keep the first entry and restore defaults for later conflicts.
- Rebinding reaches movement, jump, throw, item use, interact, the pause menu, resuming from pause, and the HUD hint.
- Fullscreen uses `fullscreenTarget: 'game'` and is intentionally not written to the save.

## Browser matrix

Playwright runs Chromium by default. Setting `BROWSER_MATRIX=1` adds Edge, Firefox, and WebKit projects:

```powershell
$env:BROWSER_MATRIX=1
npx playwright test
```

| Browser         | Version               | Coverage       | Result               |
| --------------- | --------------------- | -------------- | -------------------- |
| Chromium        | Playwright 1.64       | Full suite     | 48 passed            |
| Microsoft Edge  | Installed system Edge | 16 smoke tests | 16 passed            |
| Firefox         | Playwright build      | 16 smoke tests | 16 passed            |
| WebKit (Safari) | Playwright build      | 16 smoke tests | 13 passed, 3 skipped |

The matrix projects run the title, movement, pause, settings, audio, and accessibility specs. Boss, combat, and timing-heavy specs stay Chromium-only because they tune to one software renderer; running the entire suite per browser is an M7 CI task.

WebKit limitations found during the matrix run:

- Playwright's WebKit build on Windows has no Web Audio (`AudioContext` and `webkitAudioContext` are both missing), and its HTML5 audio element cannot decode WAV (`MEDIA_ERR_SRC_NOT_SUPPORTED`). Phaser's HTML5 fallback therefore never fired `canplaythrough` and the loader waited in `Preload` forever. Preload now detects the missing backend, skips the pack, and boots silently; playback paths check the audio cache first. The three audio specs skip on WebKit only. Real Safari has Web Audio and loads the pack.
- Two movement assertions waited a fixed number of milliseconds and then released the key. WebKit's software renderer runs fewer physics steps in that window, so the tests now hold the key until the player actually crosses the position threshold. Aim-down is also held for a frame before jump so the drop-through sees both inputs in one step.
- The WebKit project forces `deviceScaleFactor: 1`. Playwright's `Desktop Safari` profile uses a 2× DPR; with software rendering the frame rate collapses and Phaser's clamped delta makes physics run in slow motion, so a 250 ms drop-through window expires before the player moves. That is a headless-renderer artifact, not Safari behavior on a GPU. DPR-independent scaling is covered by the 1080p visual QA and by Chromium runs.

## Performance

Measured on the M6 build at 1920×1080 (4× the internal resolution) over a 5-second `requestAnimationFrame` sample in Shaft Entrance:

| Run                                       | Frames | FPS   | p50 frame | p95 frame | JS heap |
| ----------------------------------------- | -----: | ----- | --------: | --------: | ------: |
| Chromium headless, software (SwiftShader) |    301 | 60.21 |   16.7 ms |   16.7 ms |  ~20 MB |
| Chromium headed, hardware                 |    301 | 60.07 |   16.7 ms |   16.8 ms |  ~19 MB |

- Production bundle: 1,563 kB JavaScript (407 kB gzip) and 0.86 kB CSS; Phaser is the only runtime dependency.
- First load: 116 requests, about 1.73 MB transferred, of which the audio pack is the largest share.
- Budgets from the technical plan still hold: 60 FPS, under 200 particles, and no more than 8 active enemies or 40 projectiles per room.

## Production build scan

`npm run build` passes and the emitted bundle contains:

- 0 occurrences of `__MINES_TEST__`, `__MINES_DEBUG__`, or `__MINES_GAME__`.
- 0 occurrences of `boss=1`, `spawn=exit`, `URLSearchParams`, or `location.search`.

The remaining `level=` and `difficulty=` hits are property assignments such as `this.level=` and `difficulty = getDifficulty(...)`, not query strings. Development shortcuts (`?boss=1`, `?spawn=exit`, `?level=`, `?difficulty=`) still work in `npm run dev`; the whole query block sits inside an `import.meta.env.DEV` branch so Rollup drops it from production.

## Manual release checklist

Run these before tagging M7's release candidate:

1. Walk every level from spawn to elevator; jump onto every platform and confirm none is unreachable (the BFS reachability unit test covers the authored map, a human confirms the feel).
2. Trigger the pause menu mid-jump, mid-flash, and during boss telegraphs.
3. Start a run, quit from pause, start a new run; repeat twice to confirm the old hang stays gone.
4. Complete a Normal run with only rocks and read every Results line.
5. Win with each badge broken and confirm Results explains the reason.
6. Cycle flash and shake to `off`, take boss damage, and confirm the pause menu is still readable.
7. Toggle fullscreen in and out, then reload; confirm the window and save are healthy.
8. Mute during the boss fight, reload, and confirm the setting stuck.
9. Rebind jump to an unusual key, finish a level, and confirm the HUD hint matches.
10. Corrupt the save in devtools and confirm the backup and Title notice.
11. Check 1366×768, 1920×1080, and 2560×1440 for letterboxing and readable text.
